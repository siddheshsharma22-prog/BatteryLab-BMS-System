   161→   216→## Step 3: EDIT - Content Transformation
   162→   217→
   163→   218→**Before writing any code, restructure raw text into visual roles.** This is the most impactful quality step - skipping it produces "Word document with a PDF extension".
   164→   219→
   165→   220→### 3a. Typographic Role Extraction
   166→   221→
   167→   222→Parse raw text and categorize content into visual roles:
   168→   223→
   169→   224→| Role | ReportLab Mapping | Description |
   170→   225→|------|------------------|-------------|
   171→   226→| **Hero / Display** | Cover title (36-42pt) or section opener | 1-5 words, the emotional hook |
   172→   227→| **Kicker / Eyebrow** | Subtitle or section intro (10-12pt, muted) | Tiny context line above main heading |
   173→   228→| **Data Sculpture** | CalloutBox or bold stat block | Extract impactful numbers (97%, $4.2M, -45ms) |
   174→   229→| **Pull Quote** | BlockQuote (italic + left indent 24pt + accent border) | Most provocative sentence, standalone |
   175→   230→| **Body** | Standard paragraph | Everything else |
   176→   231→
   177→   232→**Rule**: Before writing any body paragraph, scan for numbers with units. Every metric like "revenue grew by 12%" or "latency dropped to 45ms" MUST be extracted into a CalloutBox or metrics table - never buried in paragraph prose. See §Data-to-Ink Ratio Rules below.
   178→   233→
   179→   234→### 3b. Section Pacing
   180→   235→
   181→   236→- If any H1 section has **>400 words** of continuous body text without visual breaks, split into H2 subsections or insert a visual break (table, chart, callout)
   182→   237→- Aim for at least 1 visual element (table/chart/callout) per 2-3 pages of body text
   183→   238→- Dense text walls are the #1 sign of poor report design
   184→   239→
   185→   240→### 3c. Content Sanitization for External Sources (MANDATORY when source is PDF/OCR/web)
   186→   241→
   187→   242→When content is extracted from an external PDF, OCR output, or web scrape, it may contain invisible garbage characters that cause garbled rendering. **You MUST sanitize the text content before writing it into any `Paragraph()` or `canvas.drawString()`.**
   188→   243→
   189→   244→This is different from `code.sanitize` (which cleans Python source code). Content sanitization cleans the **text data itself**.
   190→   245→
   191→   246→```python
   192→   247→import re
   193→   248→
   194→   249→def content_sanitize(text: str) -> str:
   195→   250→    """Strip invisible/control chars from externally-sourced text."""
   196→   251→    # Remove control chars (except \n \t)
   197→   252→    text = re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f\x7f]', '', text)
   198→   253→    # Remove zero-width chars
   199→   254→    text = re.sub(r'[\u200b-\u200f\u2028-\u202f\u2060\ufeff]', '', text)
   200→   255→    # Remove replacement char (upstream encoding error)
   201→   256→    text = text.replace('\ufffd', '')
   202→   257→    # Remove variation selectors
   203→   258→    text = re.sub(r'[\ufe00-\ufe0f]', '', text)
   204→   259→    # Remove private use area chars
   205→   260→    text = re.sub(r'[\ue000-\uf8ff]', '', text)
   206→   261→    return text
   207→   262→```
   208→   263→
   209→   264→**When to use:**
   210→   265→| Source | Must sanitize? |
   211→   266→|--------|---------------|
   212→   267→| User typed text in prompt | No (usually clean) |
   213→   268→| Extracted from PDF via `pdf.py extract.text` | **YES** |
   214→   269→| OCR output | **YES** |
   215→   270→| Web scrape / HTML strip | **YES** |
   216→   271→| LLM-generated content | No (usually clean) |
   217→   272→
   218→   273→⚠️ **Do NOT confuse** `code.sanitize` (Step 6, cleans Python code) with `content_sanitize()` (Step 3, cleans text data). They solve different problems.

   247→   302→## Character Safety Rule (MANDATORY)
   248→   303→
   249→   304→Three rules for safe character handling in ReportLab PDFs:
   250→   305→
   251→   306→**a) Superscripts and subscripts**: Use `<super>`/`<sub>` tags, never raw Unicode superscript/subscript characters (e.g., `\u00b2`, `\u2082`).
   252→   307→
   253→   308→**b) Emoji**: ReportLab cannot render emoji. If content contains emoji, use Creative brief (HTML + Playwright).
   254→   309→
   255→   310→**c) Font fallback for mixed CJK/Latin text (MANDATORY)**: After registering fonts, you **MUST** call `install_font_fallback()` once. This automatically wraps missing-glyph characters in `<font>` tags inside every `Paragraph()`. No manual `<font name="...">` wrapping needed for mixed Chinese-English text. **Skipping this call is the #1 cause of Helvetica garbled text in CJK documents.**
   256→   311→
   257→   312→**d) canvas.drawString / drawRightString CJK font rule (MANDATORY)**: `install_font_fallback()` only works on `Paragraph()` objects. It does NOT affect `canvas.drawString()` / `canvas.drawRightString()` / `canvas.drawCentredString()`. If the text passed to any `canvas.draw*String()` call contains CJK characters (Chinese/Japanese/Korean), you **MUST** call `canvas.setFont('NotoSerifSC', size)` (or another registered CJK font) before drawing. Using FreeSerif / Helvetica / Times for CJK canvas text = garbled output.
   258→   313→
   259→   314→```python
   260→   315→# ❌ WRONG — FreeSerif has no CJK glyphs, '科大讯飞' will be garbled
   261→   316→canvas.setFont('FreeSerif-Italic', 8)
   262→   317→canvas.drawRightString(x, y, 'SZSE: 002230  ·  科大讯飞')
   263→   318→
   264→   319→# ✅ CORRECT — use CJK font for mixed text
   265→   320→canvas.setFont('NotoSerifSC', 8)
   266→   321→canvas.drawRightString(x, y, 'SZSE: 002230  ·  科大讯飞')
   267→   322→
   268→   323→# ✅ ALSO CORRECT — pure English text can use FreeSerif
   269→   324→canvas.setFont('FreeSerif-Italic', 8)
   270→   325→canvas.drawString(x, y, 'Prepared by Strategy Advisory Team')
   271→   326→```
   272→   327→
   273→   328→Mathematical/relational operators (×, ÷, ±, ≤, √, ∑, ≅, ∫, π, ∠, Δ, etc.) are safe to use as literal characters in `Paragraph()` - both Noto Sans SC and FreeSerif have these glyphs.
   274→   329→
   275→   330→| Need | Correct Method | Correct Example |
   276→   331→|------|---------------|---------|
   277→   332→| Superscript | `<super>` tag in `Paragraph()` | `Paragraph('10<super>2</super> × 10<super>3</super> = 10<super>5</super>', style)` |
   278→   333→| Subscript | `<sub>` tag in `Paragraph()` | `Paragraph('H<sub>2</sub>O', style)` |
   279→   334→| Bold | `<b>` tag in `Paragraph()` | `Paragraph('<b>Title</b>', style)` |
   280→   335→| Math operators | Literal char in `Paragraph()` | `Paragraph('AB ⊥ AC, ∠A = 90°, and ΔABC ≅ ΔDCF', style)` |
   281→   336→| Scientific notation | Combined tags in `Paragraph()` | `Paragraph('1.2 × 10<super>8</super> kg/m<super>3</super>', style)` |
   282→   337→
   283→   338→```python
   284→   339→from reportlab.platypus import Paragraph
   285→   340→from reportlab.lib.styles import ParagraphStyle
   286→   341→from reportlab.lib.enums import TA_LEFT, TA_CENTER, TA_JUSTIFY
   287→   342→
   288→   343→body_style = ParagraphStyle(
   289→   344→    name="ENBodyStyle",
   290→   345→    fontName="FreeSerif",
   291→   346→    fontSize=10.5,
   292→   347→    leading=18,
   293→   348→    alignment=TA_JUSTIFY,
   294→   349→)
   295→   350→
   296→   351→# CJK Body (Chinese documents)
   297→   352→cn_body_style = ParagraphStyle(
   298→   353→    name="CNBodyStyle",
   299→   354→    fontName="NotoSerifSC", fontSize=10.5, leading=18,
   300→   355→    alignment=TA_LEFT,      # ← NEVER TA_JUSTIFY for CJK
   301→   356→    wordWrap='CJK',         # ← MANDATORY for CJK
   302→   357→    firstLineIndent=2*4.5*mm,
   303→   358→)
   304→   359→
   305→   360→# Superscript: area unit
   306→   361→Paragraph('Total area: 500 m<super>2</super>', body_style)
   307→   362→
   308→   363→# Subscript: chemical formula
   309→   364→Paragraph('The reaction produces CO<sub>2</sub> and H<sub>2</sub>O', body_style)
   310→   365→
   311→   366→# Scientific notation
   312→   367→Paragraph('Speed of light: 3.0 × 10<super>8</super> m/s', body_style)
   313→   368→
   314→   369→# Combined
   315→   370→Paragraph('E<sub>k</sub> = mv<super>2</super>/2', body_style)
   316→   371→
   317→   372→# Bold heading
   318→   373→Paragraph('<b>Chapter 1: Introduction</b>', header_style)
   319→   374→
   320→   375→# Math symbols
   321→   376→Paragraph('When ∠ A = 90°, AB ⊥ AC and ΔABC ≅ ΔDEF', body_style)
   322→   377→```
   323→   378→
   324→   379→**Pre-generation check - before writing ANY string, ask:**
   325→   380→> "Does this string contain a character outside basic CJK or Mathematical/relational operators?"
   326→   381→> If YES → it MUST be inside a `Paragraph()` with the appropriate tag.
   327→   382→> If it is a superscript/subscript digit in raw unicode escape form → REPLACE with `<super>`/`<sub>` tag.
   328→   383→
   329→   384→**NEVER rely on post-generation scanning. Prevent at the point of writing.**
   330→   385→
   331→   386→**Encoding safety - before writing ANY content text:**
   332→   387→> "Does this string contain Japanese kana (の, が, は etc.) or rare Unicode symbols?"
   333→   388→> If YES → REPLACE with safe plain Chinese equivalents. Japanese kana (Hiragana U+3040-U+309F, Katakana U+30A0-U+30FF) frequently corrupt to U+FFFD (�) when code passes through LLM output, heredoc, or terminal encoding layers.
   334→   389→> Common safe replacements: `活の真鲷`→`活缔真鲷`, `盐烤の鲭鱼`→`盐烤鲭鱼`, `烤の鸡串`→`炭烤鸡串`.
   335→   390→> If the character is genuinely needed, verify it survives a full write→read round-trip with `open(file, encoding='utf-8')`.

   361→   416→
   362→   417→### Font Registration Template
   363→   418→```python
   364→   419→from reportlab.pdfbase import pdfmetrics
   365→   420→from reportlab.pdfbase.ttfonts import TTFont
   366→   421→from reportlab.pdfbase.pdfmetrics import registerFontFamily
   367→   422→
   368→   423→import platform
   369→   424→_IS_MAC = platform.system() == 'Darwin'
   370→   425→if _IS_MAC:
   371→   426→    FONT_DIR = os.path.expanduser('~/.openclaw/workspace/fonts')
   372→   427→else:  # Linux
   373→   428→    FONT_DIR = '/usr/share/fonts'
   374→   429→
   375→   430→# Chinese fonts — Noto Serif SC (primary, serif, high quality)
   376→   431→pdfmetrics.registerFont(TTFont('NotoSerifSC', f'{FONT_DIR}/truetype/noto-serif-sc/NotoSerifSC-Regular.ttf'))
   377→   432→pdfmetrics.registerFont(TTFont('NotoSerifSC-Bold', f'{FONT_DIR}/truetype/noto-serif-sc/NotoSerifSC-Bold.ttf'))
   378→   433→# Chinese fonts — fallback / sans-serif (static weight files, NOT variable font)
   379→   434→pdfmetrics.registerFont(TTFont('Noto Sans SC', f'{FONT_DIR}/truetype/chinese/NotoSansSC-Regular.ttf'))
   380→   435→pdfmetrics.registerFont(TTFont('Noto Sans SC Bold', f'{FONT_DIR}/truetype/chinese/NotoSansSC-Bold.ttf'))
   381→   436→pdfmetrics.registerFont(TTFont('SarasaMonoSC', f'{FONT_DIR}/truetype/chinese/SarasaMonoSC-Regular.ttf'))
   382→   437→
   383→   438→# English fonts — FreeSerif (4 weights)
   384→   439→pdfmetrics.registerFont(TTFont('FreeSerif', f'{FONT_DIR}/truetype/freefont/FreeSerif.ttf'))
   385→   440→pdfmetrics.registerFont(TTFont('FreeSerif-Bold', f'{FONT_DIR}/truetype/freefont/FreeSerifBold.ttf'))
   386→   441→pdfmetrics.registerFont(TTFont('FreeSerif-Italic', f'{FONT_DIR}/truetype/freefont/FreeSerifItalic.ttf'))
   387→   442→pdfmetrics.registerFont(TTFont('FreeSerif-BoldItalic', f'{FONT_DIR}/truetype/freefont/FreeSerifBoldItalic.ttf'))
   388→   443→
   389→   444→# Symbol/Formula font
   390→   445→pdfmetrics.registerFont(TTFont('DejaVuSans', f'{FONT_DIR}/truetype/dejavu/DejaVuSansMono.ttf'))
   391→   446→
   392→   447→# CRITICAL: Register font families to enable <b>, <i>, <super>, <sub> tags
   393→   448→registerFontFamily('NotoSerifSC', normal='NotoSerifSC', bold='NotoSerifSC-Bold')
   394→   449→registerFontFamily('Noto Sans SC', normal='Noto Sans SC', bold='Noto Sans SC Bold')
   395→   450→registerFontFamily('FreeSerif', normal='FreeSerif', bold='FreeSerif-Bold', italic='FreeSerif-Italic', boldItalic='FreeSerif-BoldItalic')
   396→   451→registerFontFamily('DejaVuSans', normal='DejaVuSans', bold='DejaVuSans')
   397→   452→```
   398→   453→
   399→   454→### Font Configuration by Document Type
   400→   455→
   401→   456→**For Chinese PDFs:**
   402→   457→- Body text: `NotoSerifSC` (primary) — serif font with sharp, elegant strokes
   403→   458→- Headings: `NotoSerifSC-Bold` (MUST use for Chinese headings) — same family, bolder weight for clear hierarchy
   404→   459→- Code blocks: `SarasaMonoSC`
   405→   460→- Formulas/symbols: `DejaVuSans`
   406→   461→- **In tables: ALL Chinese content MUST use `NotoSerifSC`, numbers use `FreeSerif`**
   407→   462→- Fallback: `Noto Sans SC` (if NotoSerifSC unavailable)
   408→   463→
   409→   464→**For English PDFs:**
   410→   465→- Body text: `FreeSerif`
   411→   466→- Headings: `FreeSerif` (MUST use for English headings)
   412→   467→- Code blocks: `DejaVuSans`
   413→   468→- **In tables: ALL English content and numbers MUST use `FreeSerif`**
   414→   469→
   415→   470→**For Mixed Chinese-English PDFs:**
   416→   471→- Call `install_font_fallback()` once after registering fonts - it automatically wraps characters in `<font>` tags so you don't need to do it manually.
   417→   472→- If you still want manual control, you can use `<font name='...'>` tags, but the automatic fallback handles most cases.
   418→   473→
   419→   474→```python
   420→   475→import sys, os
   421→   476→sys.path.insert(0, os.path.join(os.path.dirname(__file__), 'scripts'))
   422→   477→from pdf import install_font_fallback
   423→   478→
   424→   479→# 1. Register fonts (as above)
   425→   480→# 2. Install fallback - one line, handles all mixed-language text
   426→   481→install_font_fallback()
   427→   482→
   428→   483→# 3. Just write naturally - no manual <font> wrapping needed!
   429→   484→en_style = ParagraphStyle(name="EN", fontName="FreeSerif", fontSize=10.5, leading=18)
   430→   485→cn_style = ParagraphStyle(name="CN", fontName="NotoSerifSC", fontSize=10.5, leading=18, wordWrap='CJK')
   431→   486→
   432→   487→Paragraph('MySQL、PostgreSQL、Redis', en_style)           # ✅ CJK comma auto-fallback to NotoSerifSC
   433→   488→Paragraph('Beijing (北京) has 21M people', en_style)       # ✅ CJK chars auto-fallback
   434→   489→Paragraph('价格:¥2,200~5,800/月', en_style)               # ✅ all CJK chars handled
   435→   490→Paragraph('《巴黎协定》签署于2015年', en_style)               # ✅ CJK book title marks handled
   436→   491→```
   437→   492→
   438→   493→**How it works:** `install_font_fallback()` monkey-patches `Paragraph.__init__` to scan each character against the font's `charToGlyph` table. Characters missing from the base font are automatically wrapped in `<font name="FallbackFont">`. The fallback chain is: English fonts → NotoSerifSC (primary) or Noto Sans SC (legacy), Chinese fonts → FreeSerif. For aesthetic optimization, Cyrillic text in NotoSerifSC/Noto Sans SC is automatically routed to FreeSerif (serif looks better for Cyrillic).

   459→   514→## Layout & Spacing Control
   460→   515→
   461→   516→### Page Breaks
   462→   517→
   463→   518→Follow the document type strategy defined in SOUL.md Rule 1.
   464→   519→
   465→   520→**Structural breaks (always - MANDATORY):**
   466→   521→- Between cover page and TOC - **cover must NEVER share a page with anything else**
   467→   522→- Between TOC and main content
   468→   523→- Between main content and back cover
   469→   524→
   470→   525→**Content breaks (by document type):**
   471→   526→- **Default (all document types)**: ❗ **Absolutely NEVER force page breaks before H1/H2** — content flows naturally, do not insert `PageBreak()` before section headings. This is an iron rule.
   472→   527→- Resume / contract / letter → No content page breaks
   473→   528→- Short article → No content page breaks
   474→   529→- **Exception 1**: Academic papers / textbooks / teaching plans → `PageBreak()` before each H1 is acceptable (only if user explicitly requests academic formatting)
   475→   530→- **Exception 2**: User explicitly requests page breaks between chapters
   476→   531→
   477→   532→**Anti-tear (mandatory — but with height limit):**
   478→   533→```python
   479→   534→from reportlab.platypus import KeepTogether
   480→   535→from reportlab.lib.pagesizes import A4
   481→   536→from reportlab.lib.units import inch
   482→   537→
   483→   538→# Maximum height for KeepTogether blocks: 40% of page height
   484→   539→# Blocks taller than this should NOT be kept together — they cause
   485→   540→# the preceding page to be mostly empty when the block gets pushed down.
   486→   541→MAX_KEEP_HEIGHT = A4[1] * 0.4  # ~336pt ≈ 12cm
   487→   542→
   488→   543→def safe_keep_together(elements):
   489→   544→    """Wrap elements in KeepTogether only if their total height is reasonable.
   490→   545→    If too tall, keep only the FIRST TWO elements together (e.g. title + table/image header)
   491→   546→    to prevent title-content separation, while letting the rest paginate naturally.
   492→   547→    """
   493→   548→    total_h = 0
   494→   549→    for el in elements:
   495→   550→        w, h = el.wrap(A4[0] - 2*inch, A4[1])
   496→   551→        total_h += h
   497→   552→    if total_h <= MAX_KEEP_HEIGHT:
   498→   553→        return [KeepTogether(elements)]
   499→   554→    elif len(elements) >= 2:
   500→   555→        # Keep at least title + first element together to prevent title orphaning
   501→   556→        return [KeepTogether(elements[:2])] + list(elements[2:])
   502→   557→    else:
   503→   558→        return list(elements)
   504→   559→
   505→   560→# Heading stays with first paragraph
   506→   561→story.extend(safe_keep_together([
   507→   562→    heading_paragraph,
   508→   563→    first_body_paragraph,
   509→   564→]))
   510→   565→
   511→   566→# Image + caption: keep together ONLY if image is small
   512→   567→story.extend(safe_keep_together([image, caption_paragraph]))
   513→   568→
   514→   569→# Table title + table: keep together ONLY if table is short
   515→   570→if len(table_data) <= 15:
   516→   571→    story.extend(safe_keep_together([table_title, table]))
   517→   572→else:
   518→   573→    # Long table: just keep title with the table start
   519→   574→    story.extend(safe_keep_together([table_title]))
   520→   575→    story.append(table)
   521→   576→```
   522→   577→
   523→   578→**⚠️ KEY INSIGHT:** `KeepTogether` is the #1 cause of “empty page with chart on next page”.
   524→   579→When a `KeepTogether` block is taller than the remaining space on the current page,
   525→   580→ReportLab pushes the **entire block** to the next page, leaving the current page mostly empty.
   526→   581→**Always use `safe_keep_together()` to cap the maximum block height.**
   527→   582→
   528→   583→**⚠️ Note:** Do NOT use `KeepWithNext` - it is unreliable in ReportLab 4.x.
   529→   584→
   530→   585→### Vertical Spacing Standards
   531→   586→* Before tables: `Spacer(1, 18)` after preceding text
   532→   587→* After tables: `Spacer(1, 6)` before table caption
   533→   588→* After table captions: `Spacer(1, 18)` before next content
   534→   589→* Between paragraphs: `Spacer(1, 12)` (~1 line)
   535→   590→* Between H3 subsections: `Spacer(1, 12)`
   536→   591→* Between H2 sections: `Spacer(1, 18)` (~1.5 lines)
   537→   592→* Between H1 sections: `Spacer(1, 24)` (~2 lines)
   538→   593→* NEVER use `Spacer(1, X)` where X > 24, except for H1 major breaks or cover page elements

   540→   595→### Cover Page: HTML/Playwright Unified Cover System
   541→   596→
   542→   597→**⚠️ Report route covers are ALWAYS generated via HTML/Playwright**, using the same 5-template system defined in `typesetting/cover.md`. This ensures visual consistency across all routes (Report, Creative, Academic) and avoids the limitations of ReportLab for complex cover layouts.
   543→   598→
   544→   599→**Pipeline (Report route):**
   545→   600→1. Generate **body PDF** via ReportLab (start with TOC or content - **no cover in story[]**)  
   546→   601→2. Generate **cover HTML** following `typesetting/cover.md` 5-template system  
   547→   602→3. **Run `poster_validate.py check-html` on cover HTML** — fix any ERRORs before rendering (overflow:hidden, font fallback, etc.)  
   548→   603→4. **Run `cover_validate.js` on cover HTML** — detects text-vs-decorative-line overlaps. Non-zero exit = must fix before proceeding.
   549→   604→   ```bash
   550→   605→   node "$PDF_SKILL_DIR/scripts/cover_validate.js" cover.html
   551→   606→   ```
   552→   607→5. Render cover HTML → single-page PDF via Playwright (`html2poster.js`) — **NOT `html2pdf-next.js`** (which converts absolute→static and destroys cover layout). **⚠️ MUST pass `--width 794px` for A4 documents** (A4 = 210mm = 794px @96dpi). Without this, `html2poster.js` defaults to 720px (=540pt), which is narrower than A4 (595pt) and causes page size mismatch after merging with the body PDF.  
   553→   608→6. **Merge: insert cover as page 0** of body PDF using pypdf → output single final PDF
   554→   609→
   555→   610→> **Why not ReportLab covers?** ReportLab is excellent for structured content (tables, paragraphs, flowables) but painful for visual design (geometric accents, precise absolute positioning, web fonts). HTML/CSS handles these natively. One cover system, one visual standard, zero inconsistency.

   557→   612→**⚠️ Cover page is DEFAULT ON for all Report-route documents ≥ 3 pages.**
   558→   613→
   559→   614→The Report route handles formal, structured documents. Readers expect a professional cover. **Always generate a cover unless the document type is explicitly excluded below.**
